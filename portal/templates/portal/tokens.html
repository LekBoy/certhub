Um token permite que um pipeline de build ou um script assine ficheiros pela API, sem entrar no site e sem nunca ter acesso à chave do certificado. O token identifica a conta que o criou: as assinaturas ficam no histórico dessa conta e só pode usar os certificados a que ela tem acesso. Para pipelines, crie-o numa conta de serviço e entregue-o à equipa de forma segura.

Exemplo para o pipeline

Passo a executar depois de compilar. Se a assinatura falhar, o passo falha e o build pára (opção -f).

curl -f -X POST {{ api_url }} \
  -H "Authorization: Bearer $INFRAHUB_TOKEN" \
  -F file=@MyAction.dll \
  -F certificate={% if usable_certs|length == 1 %}{{ usable_certs.0.pk }}{% else %}ID{% endif %} \
  -o MyAction.signed.dll
  • Guarde o token como variável secreta do pipeline (INFRAHUB_TOKEN). Nunca o ponha no código nem no repositório.
  • certificate é o número do certificado a usar. Se só houver um disponível, pode omitir.
  • O ficheiro assinado vem na resposta; guarde-o com outro nome (.signed) e use-o no resto do build.
